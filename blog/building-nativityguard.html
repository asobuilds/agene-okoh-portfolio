Building NativityGuard — Architecture of a Civic-Tech Platform

How I designed a full case-lifecycle system for rural Nigerian security workflows.

GoReactPostgreSQLCivic Tech

Why I built this

In rural Nigerian communities, the gap between citizens and local security units is wide. Cases are handled informally, accountability is low, and response times suffer. There's no digital workflow for reporting incidents, tracking cases, or ensuring follow-ups happen.

NativityGuard is my attempt to close that gap with technology — while being extremely deliberate about not enabling vigilantism. It's a digital operating layer that plugs into existing lawful security institutions.

The core workflow I designed

Rather than treating this as a chat system with a dashboard, I modeled it as a case lifecycle:

signal → intake → triage → routing → assignment → dispatch → arrival → investigation → evidence → resolution → audit → prevention

Each transition is a state in the case — with an actor, a timestamp, and evidence. This makes every action auditable and prevents the "who said what" problem that plagues informal case handling.

Tech choices and why

  • Go (Gin + GORM) — I needed a fast, compile-time-checked backend with real concurrency for real-time case updates. Go's goroutines and WebSocket hub pattern handle the notification fan-out elegantly.
  • PostgreSQL with UUIDs — Cases, evidence, and audit logs are all UUID-keyed so the database can be sharded later without migration pain.
  • React 19 + Vite — Instant HMR during development, small bundle in production. Tailwind for the UI layer so I don't fight CSS naming.
  • JWT auth — Stateless API tokens. Scales horizontally from day one.
  • Redis + Docker Compose — Session cache and local dev parity. Production runs on Render.com.

What was hard

The permission model. Four roles (resident, officer, unit admin, system admin) with different scopes, geographic boundaries, and case access rules. I ended up encoding this as a small policy engine on top of JWT claims rather than scattering if user.role === 'admin' everywhere.

GIS without a GIS team. The crime-index map uses PostGIS with a lightweight GeoJSON serializer. Serving vector tiles is out of scope for v1 — I'm using clustered marker aggregation instead.

Designing for distrust. Communities wary of surveillance need to trust that the system can't be weaponized. That drove the audit-log-by-default decision and the explicit "does not replace lawful institutions" framing.

A decision I'd revisit

I built the case state machine with string columns rather than a proper FSM library. It works, but adding a new state means touching validation, migrations, and the UI in three places. If I rebuilt, I'd use a transition table with an enum type from day one.

What's next

The intelligence tier (Python + FastAPI + scikit-learn + GeoPandas) is next — anomaly detection on incident patterns, hotspot prediction, and image analysis for evidence triage. MLflow for model versioning.

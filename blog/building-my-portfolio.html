I Rebuilt My Portfolio From Scratch — Here's Everything That Broke

From a single long page to a full ecosystem: design system, multi-page architecture, SEO, blog, contact funnel, and the mistakes I'd repeat again.

The starting point

My original portfolio was one long HTML page. It had all the right pieces — about, experience, projects, skills, contact — stacked vertically. Recruiters would scroll, get tired, and bounce. Project links were buried halfway down. No blog. No way to rank in search. And most importantly: no clear pitch to a potential client. It read like a résumé, not a business.

So I rebuilt the whole thing from scratch. Here's what that looked like.

Decision 1 — Multi-page, not single page

Every major section became its own page: Home, About, Experience, Projects, Services, Process, Contact, Writing, plus a 404. Each project also got its own case study.

Why this matters: search engines rank pages, not sections. A dedicated page for NativityGuard can rank for "civic tech Nigeria" in a way that a single-page scroll never could. A recruiter looking for a specific project now lands directly on it.

Decision 2 — A real design system

I pulled every color, spacing value, font size, shadow, and border-radius into CSS variables at the top of one stylesheet. That gave me three wins instantly:

  • Dark mode is six lines of code — just swap the variables
  • Consistency across all 17 pages without copy-pasting values
  • Speed — one file to edit when I want to change the accent color

The design language is deliberately "developer-native": monospace accents, a status bar that looks like a shell prompt, a terminal overlay on Ctrl + \`. It signals the audience I want without needing to spell it out.

Decision 3 — A build log (you're reading it)

A portfolio shows what you can do. A blog shows how you think. I added a /blog section for exactly this — build logs, architecture notes, lessons. Every post is a written artifact that ranks in search and gives recruiters a way to evaluate my reasoning before they ever meet me.

The posts already live: how I built NativityGuard, why I reach for Go, what AI in agriculture actually needs, how DevCraft Career works, my first paying client. This one makes six.

Decision 4 — Ship on Vercel, wire everything

Zero-cost hosting on a global CDN, instant deployments on every push, HTTPS included. I connected:

  • Formspree for the contact form — submits land in my inbox within seconds
  • Vercel Analytics — I can see which pages recruiters actually open
  • Google Search Console — property verified, sitemap submitted, pages indexing
  • OpenGraph tags — links I paste into LinkedIn show a real preview card
  • Custom security headers via vercel.json

What broke — and what I learned

Three things went wrong that are worth documenting:

1. My résumé PDF was HTML mislabeled as .pdf. I printed the page from Chrome, saved as PDF, and it opened as garbage. The fix was using Microsoft Edge's headless print-to-PDF from the command line. Lesson: verify any file you're going to hand to a recruiter by opening it in a fresh viewer, not just trusting the extension.

2. At one point my homepage literally contained the text `C:\Users\USER`. A stray PowerShell redirection wrote a path into index.html instead of running as intended. Deployed silently. Only caught it by curl-ing my own live site. Lesson: after every deploy, curl the live URL and confirm the response isn't wrong, not just present.

3. Edge's headless screenshots "failed" for 5 minutes. The script checked for the output file before Edge finished writing it. Adding a 3-second wait fixed it. Lesson: when a tool is asynchronous, don't test for its output immediately — or test with a retry loop.

None of these were disasters. All of them are the actual work of shipping.

What I'd do differently next time

If I were rebuilding today, I'd use Astro or 11ty instead of hand-written static HTML. Same static output, same performance, but shared layouts and content collections would make the blog 10× faster to maintain. Every new post would be one Markdown file, not one 200-line HTML file.

I'd also add testimonials earlier — they're the highest-leverage content on the site. I had them at the end, but they should have been above the fold from day one.

The result

Live at agene-okoh.vercel.app — a portfolio that doubles as its own case study. Six projects, six blog posts, working contact funnel, SEO plumbing, analytics, and a design system I can extend without rewriting anything.

More importantly: it's the first version of a system I'll keep shipping on. Every new project, every new post, is one commit away from being live.

The takeaway

A portfolio isn't a page — it's a system. Build it like one. Design it to grow. Document the process. Then let the work speak.

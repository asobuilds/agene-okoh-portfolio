The Honest State of My Work

What's shipped, what's cooking, and why I'd rather show real progress than polished fiction.

Build in PublicCareerEngineering

Why I'm writing this

Developers are trained to show finished work. The screenshots are polished, the numbers are rounded up, the dead ends are hidden. It looks impressive — and it teaches nothing.

So here's the version I'd want to read from someone else: an honest state of my work. What's done, what's half-built, and what I'm still figuring out. No rounding up.

✅ Complete and in use

LeadClear Journal — Client work, live

A landing page I built for Anne Abiodun's 30-day leadership journal. It's wired into her Selar checkout for payments and Systeme.io for the email funnel. She's using it right now with real customers. This is the only project on this list where someone else's business depends on my code — and that's a different kind of pressure.

Stack: HTML/CSS/JS · Selar · Systeme.io · Vercel

My portfolio — Live

Rebuilt from a single long page into a full ecosystem: 6 case studies, a build log (you're reading it), a working contact funnel, SEO, analytics, dark mode, and a design system I can extend in minutes. I broke it twice during the rebuild. Documented both.

Stack: Static HTML/CSS/JS · Vercel · Formspree · Vercel Analytics

🚧 In progress — 60 to 80%

DevCraft Career — ~65%

A CV builder with an AI job matcher. Users build a professional CV in minutes; the system scans private, government, and freelance listings and sends them the direct apply link. The CV builder works. The job scanner works. What's left: better matching, application tracking, and enough polish that I'd put it in front of a stranger.

Stack: React · Python · Job APIs · Vercel

NativityGuard — ~60%

A civic-tech platform bridging rural Nigerian communities and local security units. Full case lifecycle (12 states — signal → intake → dispatch → investigation → audit), a GIS crime-index map, SOS alerts, WebSocket live updates, JWT auth across 4 user roles.

The API and system of record are Go + PostgreSQL. The frontend is React 19. The intelligence tier (Python + ML for anomaly detection) hasn't started. It runs end-to-end in dev. It's not ready for a pilot unit yet.

Stack: Go 1.21 · Gin · React 19 · PostgreSQL · PostGIS · Redis · Docker

Plant Assistant — ~70%

An AI tool for small-scale farmers. Snap a photo of a plant, get identification, care advice, and season-specific pesticide recommendations based on geolocation. Offline-first PWA. The model works on the target species. What's left: field testing with actual farmers, offline caching edge cases, and a mobile interface that doesn't drain battery.

Stack: Python · scikit-learn · Streamlit prototype · PWA target

My Creative Partner — collaborative, ~50%

A 3D philosophical game where text and voice prompts generate visualizations of user ideas. It's a team effort — I'm not the only owner. Real-time generation pipeline is the hardest part we're still working through.

Stack: 3D · AI · Voice Interface · Text Prompting

Why I'm posting this honestly

Because building quietly doesn't help anyone.

Future clients can't hire what they can't see. Recruiters can't evaluate a developer who hides their process. And other builders learn more from watching progress than from staring at finished screenshots.

There's a version of this where I wait six months, polish everything to 95%, and then post a triumphant launch thread. That version is boring, and it doesn't reflect how software actually gets built.

Shipping isn't an event. It's a habit.
